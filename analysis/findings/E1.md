## Out of scope, noticed
- `do_search` (`search_symbols`, mod.rs:313) guards its merge arm with `if section != SECTION_SEMANTIC` and hard-codes `semantic: None`, so the structural-only tool is genuinely unaffected by the embedder — an existing, zero-change escape hatch for exact-name lookup.
- Dedup keeps the *first* occurrence and the name section is emitted first, so a symbol found by both sections is scored by name relevance, never by cosine: the merge is asymmetric in the name section's favour on score, and loses only on rank.
- `clamp_limit` maps `Some(0)` to `MAX_LIMIT` (500), not to the default (mod.rs:2018-2025) — `limit: 0` returns 500 rows.
- `fetched_may_have_capped` is set when *any single section* returns `>= fetch_limit` rows, so `truncated: true` on a merged response can be caused by a section the reader sees no rows from.
- `Impl` carries `kind_weight` 1.0 (hits.rs:163-172) and is not held out by the default member scope, which is why 22 `impl` blocks could rank above a discounted function.
