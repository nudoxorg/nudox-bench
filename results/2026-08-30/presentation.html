Does the index beat grep?

On the questions it was given and the packages it holds, Nudox matched ripgrep's accuracy while returning 7.4× less text, and every fact it returned was a resolved symbol rather than a line of source that happened to contain the right word. It also declined half the corpus, and one capability was switched off. Here is all of it.

Read this before the numbers

  • Semantic search was off. Every Nudox response carried ~sem:unavailable(NoModelConfigured) — no embedding model was configured, so half of what search normally ranks with was disabled. These are structural-only numbers.
  • Nudox held 3 of 5 packages. The Go oracle binary (nudox-go-oracle) is not installed, and Python's installed requests has no pyproject.toml for the producer to read. Those scenarios are recorded as declined, not failed.
  • The judge did not run. No OPENROUTER_API_KEY, so the two implementation scenarios are unscored rather than counted against anyone.
  • Ten scenarios is a small sample. Nothing here is significant in a statistical sense. It is a working instrument with first readings.

Cost against correctness

Both measures at once, because either alone is gameable: a tool can be cheap by answering nothing, or accurate by returning the package.

Note: the nudox-* rows and ripgrep are not answering the same number of questions — Nudox declined three packages it was never given. The like-for-like comparison is the per-scenario chart below.

What each answer cost

  • On callers of search_slice_with_raw, Nudox answered correctly in 1,602 tokens. ripgrep spent 27,487 and still got it wrong — it found 4 of 6 callers, because a line containing a call names the callee, never the caller.
  • On memchr's public surface, the result inverts: ripgrep passed with 18,047 tokens of ^pub lines; Nudox reached 60% for 1,205. Brute enumeration is genuinely good at enumeration.
  • rust-analyzer is the cheapest thing on the board and answers almost nothing — 39 tokens to fail a signature lookup is not a bargain.

How much was actually resolved

Every expected fact is matched twice: strict counts only a fully-qualified path; loose counts the bare identifier appearing anywhere in the returned text. The distance between them is the part of a score that is undifferentiated text rather than a resolved symbol.

  • Nudox's gap is exactly zero. Everything it returned, it returned as an address. That is the property you are buying, and it is the one that does not show up in a pass/fail column.
  • ripgrep's 5-point gap is small here only because these scenarios ask about distinctively-named symbols. It widens with common names — which is most real code.

Precision, not recall, is where text search breaks

The clearest single result in the run. On go/uuid/callers-parse, ripgrep found 100% of the expected callers and still failed — because ParseBytes landed in the output. It is an exported function whose name contains Parse, and it does not call Parse; it has its own parsing path (verified at uuid.go:120).

A benchmark that scored recall alone would have called that a perfect answer. Distractor sets are why it did not.

What the surface costs before you ask anything

  • index alone is 946 tokens, 25% of the whole surface — nearly double the next largest. It is also the tool a reading session calls zero times. Every agent pays for it on every turn regardless.
  • MCP-SURFACE-PLAN §1.1 measured the older 13-tool surface at 3,875 cl100k. Nine tools now cost 3,761 — consolidation returned about 3%, not the reduction the tool count suggests, because the surviving descriptions absorbed the prose.
  • Put in context: the fixed surface costs roughly 3× what an average answer costs. For a session asking one question, the tool descriptions are the dominant expense.

Nudox against itself

Five client-side restrictions on the same running server, so a whole sweep costs one command and no rebuild.

  • The second call earns its keep. oneshot saves 41% of the tokens and loses a scenario. Stopping after search is cheap and frequently insufficient.
  • search-only is 4.3× cheaper than the full surface and still answers 2. For an agent on a tight budget, search-then-stop is a defensible default — which is an argument for making the first response denser.
  • The escape hatch loses to the purpose-built tools. graph-first costs the same as full and answers less. The schema card is cheap (134 tokens) but writing a correct Trustfall query against it is not free.
  • The address-versus-hash ablation did not run, and that is itself the finding: search renders addresses, so the 64-hex key never crosses the wire and there was nothing to substitute. An agent does not pay the ~54-token hash unless it deliberately asks for it. The harness now reports ~ablation:not-exercised rather than a misleading identical row.

Analysis

  • The cost argument is the strong one; the accuracy argument is not yet made. On the Rust scenarios both systems could attempt, Nudox and ripgrep tie on pass rate. What separates them is an order of magnitude of tokens and a zero resolution gap. "Same answers, one-seventh the context" is a real claim. "More correct answers" is not supported by this run.
  • Nudox's one exclusive question, it got wrong — for a fixable reason. Cross-version diff is the scenario neither baseline can attempt. Nudox returned 50 changed declarations in 3,745 tokens, but ordered by path, so alloc module internals filled the page and the four added HashMap methods were past the cut. The tool worked; the ordering buried the answer, and the harness took only page one.
  • Two of the three Nudox failures were the harness using the tool wrong. The overview scenario sent a prose query ("memchr public exports") to a search that matches names and kinds — with the embedder off, it matched nothing and scored 13%. Querying the package name instead took it to 60% with no change to Nudox. This is worth stating plainly: a benchmark's first findings are usually about the benchmark.
  • The resident surface is the quiet cost. 3,761 tokens sit in context before any question, against an average answer of ~1,277. The tool descriptions outweigh the answers roughly 3:1 for a short session, and a quarter of that is one tool most sessions never call.
  • ripgrep is a much stronger baseline than it is usually given credit for. Given fair context flags, it passes 5 of 7. Anything replacing it has to win on cost, precision, or reach — not on "can it find things at all".
  • Reach is where the gap is structural, not incremental. rust-analyzer declined 5 of 10 — every non-Rust package and every cross-version question — and no amount of tuning changes that. That is the axis where an index has a defensible answer, and it is the axis this run measured least, because the Go and Python producers were unavailable.

What would make the next run decisive

  • Turn the embedder on. Set NUDOX_EMBED_MODEL_DIR and re-run. Half of search's ranking has never been measured, and the scenarios it should help most — prose questions, concept lookups — are exactly the ones Nudox lost.
  • Install the Go oracle and index a Python source checkout. Polyglot reach is the strongest structural argument and it is currently untested.
  • Grow to ~50 scenarios, weighted to disagreement. The informative scenarios are the ones where the tools diverge; ties tell you nothing. Ten is enough to debug an instrument, not to conclude with.
  • Paginate diff in the adapter. A real agent that did not find its answer on page one would ask for page two. Not doing so measures the harness's patience rather than the tool's capability.
  • Make the keys ablation real by reading the structured key field, so the address scheme's saving is priced rather than assumed.
  • Then add the MCP field. Context7, Deepcon, Exa and NIA are the comparison everyone will ask for — but only after these numbers are stable, or the result will be a story about a misconfigured harness.
  • Add an agent-driven mode. Every adapter here follows a fixed tool path. The actual product question is whether a model can drive this surface unaided, and a scripted path cannot answer it.
